# 生产级稳定性：修复 404 bug + 集成测试扩展

## Context

框架 P0 架构债清理完成后，`integration_404_for_unregistered_route` 测试失败。根因调查确认：

1. `app_base()`（`crates/core/src/paths.rs` L27-60）在测试环境中遍历 cwd 子目录查找 `appsettings.json`，命中 `output/` 目录
2. `build()` 中 SPA 自动检测（`crates/host/src/server.rs` L323-331）检查 `app_base().join("wwwroot").is_dir()` → `output/wwwroot/` 存在
3. SpaMiddleware 被激活，对未匹配 GET 路由回退到 `index.html`（`crates/spa/src/spa.rs` L91-103），返回 200
4. `make_router_handler`（server.rs L778-786）的 404 分支检查 `has_body()` 为 true → 跳过 `write_error_response`

这不是 SPA 的 bug——SPA 回退 index.html 是预期行为。问题是**测试环境意外激活了 SPA**，且生产环境也可能出现类似误激活。

同时，集成测试覆盖严重不足：仅 3 个测试，关键路径（health 端点、CORS preflight、JWT 端到端）零覆盖。

## 修复方案

### 改动 1：HostBuilder 添加 `no_spa()` 方法

**文件**：[crates/host/src/server.rs](file:///e:/GitCode/RF/rust-webx/crates/host/src/server.rs)

**为什么**：当前 SPA 自动检测无法被显式禁用。测试环境需要显式禁用 SPA 以隔离测试框架行为；生产环境若不需要 SPA 也应能禁用。符合"微软风格极致易用"——显式优于隐式。

**实现**：

1. HostBuilder struct 新增字段（L64-72 附近）：
```rust
pub struct HostBuilder {
    // ... existing fields ...
    spa_disabled: bool,  // 新增：显式禁用 SPA（包括自动检测）
}
```

2. `new()` 初始化（L96-106）：
```rust
spa_disabled: false,
```

3. 新增 `no_spa()` 方法（紧邻 `use_spa` 之后，L163-166 附近）：
```rust
/// Explicitly disable SPA, including auto-detection.
///
/// By default, the framework auto-detects `wwwroot/` under `app_base()`.
/// Call this when you want a pure API host without SPA fallback,
/// or in tests to isolate framework behavior from filesystem state.
pub fn no_spa(mut self) -> Self {
    self.spa_disabled = true;
    self
}
```

4. 修改 build() 中 SPA 自动检测逻辑（L320-334）：
```rust
let spa_root = if self.spa_disabled {
    None
} else {
    self.spa_root.clone().or_else(|| {
        let candidate = rust_webx_core::paths::app_base().join("wwwroot");
        if candidate.is_dir() {
            tracing::info!("[Host] Auto-detected SPA root: {}", candidate.display());
            Some(candidate.to_string_lossy().into_owned())
        } else {
            None
        }
    })
};
```

### 改动 6：新增 use_middleware API 测试

**文件**：新增 [crates/host/tests/builder_test.rs](file:///e:/GitCode/RF/rust-webx/crates/host/tests/builder_test.rs)

验证 `HostBuilder::use_middleware::<T>()` 注册的中间件确实进入 pipeline。

测试模式：构造一个带自定义 TrackingMiddleware 的 Host，发送请求，验证中间件被调用（通过响应头标记）。

```rust
use rust_webx_core::http::IHttpContext;
use rust_webx_core::middleware::IMiddleware;
use rust_webx_host::server::Host;
use std::ops::ControlFlow;
use std::sync::Arc;

struct MarkerMiddleware;
impl Default for MarkerMiddleware { fn default() -> Self { Self } }
#[async_trait::async_trait]
impl IMiddleware for MarkerMiddleware {
    async fn invoke(&self, ctx: &mut dyn IHttpContext) -> rust_webx_core::error::Result<ControlFlow<()>> {
        ctx.response_mut().set_header("x-marker", "yes");
        Ok(ControlFlow::Continue(()))
    }
}

#[tokio::test]
async fn use_middleware_registers_into_pipeline() {
    let port = find_free_port();
    let addr = format!("127.0.0.1:{}", port);
    let host = Host::builder()
        .mode(rust_webx_core::mode::AppMode::Development)
        .no_spa()
        .use_middleware::<MarkerMiddleware>()
        .build();
    tokio::spawn(async move { host.run_at(&addr).await.unwrap() });
    tokio::time::sleep(std::time::Duration::from_millis(500)).await;

    let resp = reqwest::get(format!("http://127.0.0.1:{}/health", port)).await.unwrap();
    assert_eq!(resp.status().as_u16(), 200);
    assert_eq!(resp.headers().get("x-marker").unwrap(), "yes");
}
```
