# 渐进式披露原则

适用于**任意框架**开发者手册的内容编排，与 API 设计中的渐进式披露同构。

## 定义

**渐进式披露**：先给出解决多数场景的最简路径，高级能力按需揭示，避免一次倾倒。

文档目标：**每一阅读层级都能产出可用成果**，而非「读完全书才能动手」。

## 通用披露层级（L0–L4）

```
L0: 最小可运行示例（Hello World / 等价物）
    ↓
L1: 首个完整业务场景（CRUD / 典型用例）
    ↓
L2: 配置、横切能力（中间件、认证、环境）
    ↓
L3: 子系统深入（按主题分章，每章一能力域）
    ↓
L4: 扩展点、边界、迁移、参考案例
```

| Level | 典型章节类型 | 写作策略 |
|-------|-------------|---------|
| L0 | introduction、quickstart | 完整可复制代码；少原理 |
| L1 | quickstart 续、first-app | 分步 + 表格；链到 L3 而非内嵌 |
| L2 | configuration、security、production | 按需链接；表格列举选项 |
| L3 | core-*、各子系统章 | 一节一主题；默认路径 + escape hatch |
| L4 | extensibility、best-practices、migration | 边界表；扩展点索引 |

**映射到具体项目：** 读该书 `INDEX.json` / 根 `INDEX.md`，将 L0–L4 对应到**实际章号**，勿假设固定「第 5 章 = 请求模式」。

## 全书 parts 与 Level 对应（新建书参考）

| Part 名称 | 建议 Level | 说明 |
|-----------|-----------|------|
| 入门与认知 | L0 | 定位、边界、生态 |
| 快速上手 | L0–L1 | 30 分钟内可跑通 |
| 设计思想与架构 | L1 | 回答「为什么」 |
| 核心开发模式 | L2–L3 | 按能力域分章 |
| 配置、安全与生产 | L2 | 上线相关 |
| 工程化与进阶 | L3–L4 | 结构、陷阱、性能 |
| 案例与迁移 | L4 | 融会贯通 |

已有书籍以现有 parts 为准；新内容插入时对照 Level，**过高 Level 的内容后移或改链接**。

## 单节内披露顺序

### 教程型（quickstart）

1. 完整代码（可运行）
2. 分步解读（编号 + 含义表）
3. 背后机制（mermaid，可选）
4. 常见变体（2–3 个短例）
5. 小结 + 下一节

### 概念型（philosophy / architecture）

1. 是什么（一句话）
2. 为什么（动机、对比表）
3. 怎么做（最小示例或原则表）
4. 边界（框架 / 应用 / 不内置）
5. 小结 + 跨章链接

### 参考型（子系统章）

1. 何时需要
2. 默认用法（80%）
3. 进阶 / escape hatch
4. 与他章关系（链接，不重复）

## 信息密度

| ✅ | ❌ |
|----|-----|
| 一节一主题 | 一节覆盖注册+路由+错误+测试 |
| 先示例后原理 | 先讲内部实现再写 Hello World |
| 跨章链接 | 在入门章复制进阶章全文 |
| 表格对比 | 长段 API 罗列 |
| 明确「下一节读 X」 | 假设读者已读全书 |

## 框架边界写法（功能文档必备）

写能力文档时同步声明（具体职责按**当前框架**填写）：

**{框架}负责：** 列框架核心职责（管线、DI、生命周期等）

**应用负责：** 业务逻辑、持久化选型、领域模型、UI、基础设施选型

**刻意不内置：** 列出有意不做的能力 + 推荐扩展点（trait / hook / 接口名）

## 扩展点披露规则

仅在默认能力不够时披露；扩展点清单因项目而异，从源码 `trait` / 扩展章读取，**勿从其他框架复制清单**。

## AI 约束

1. 新节前问：「不读本节，读者能否用该框架完成基本任务？」— 若能，本节可后移
2. 章 INDEX 导语写「读完能做什么」，非目录复述
3. FOREWORD 的阅读路径 = 全书编排权威顺序
4. 项目 Profile 中的 Level 映射优先于本文件的抽象分层

## 小结

简单场景简单写，复杂场景有路可走 —— 文档层级与框架 API 层级对齐。
