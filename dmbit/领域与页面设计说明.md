# 智算机房台账 · 领域语义与页面设计说明

> Canvas：`canvases/dmbit-domain-pages.canvas.tsx`（可随后同步）  
> 目标：手动维护精细台账 → 大屏按维度统计（含 **GPU/NPU 卡数**、**硬盘块数按规格**）。

---

## 1. 核心概念（统一用语）

| 概念 | 落库 | 一句话 | 例子 |
|------|------|--------|------|
| **产品** | `products` | 可管理的**整机型号** | RTX 5090 算力服务器；华为昇腾 910B 算力服务器；存储服务器 |
| **类别** | `products.category` | `compute` / `storage`，大屏「算力/存储」汇总依据 | 不再靠 code 字符串猜 |
| **品牌短码** | `goods.brand` | 列表扫一眼的系列短名 | `RTX5090`、`Ascend910B`、`HC320`、`定制` |
| **台账行** | `goods` | 同型号下同一状态/机位批次的**整机台数** | 150 台 · 运行中 · A区 |
| **机箱参数** | `goods.parameters` | 机箱/主板/内存/接口/扩展说明/电源/光模块等**描述性**键值 | 扩展说明可写「PCIe×6」 |
| **部件明细** | `goods_components` | **可统计**的卡/盘：型号 + 单台数量 +（盘）容量 | 每台 6 张 RTX5090；每台 36 块 8TB HC320 |

**关系：**

```
产品(Product) 1 ─── N 台账(Goods)
台账(Goods)   1 ─── N 部件(GoodsComponent)   // kind=accelerator|disk
```

- **整机台数** = `goods.quantity`  
- **某型号卡总数** = Σ(`quantity` × 该台账下 accelerator 的 `qty_per_unit`)  
- **某规格盘总数** = Σ(`quantity` × disk.`qty_per_unit`)，按 `model + capacity` 分组  

`6×RTX5090` **不得**写进 brand；必须落在部件表：`model=RTX5090, qty_per_unit=6`。

代码表名 `Goods` 界面一律称 **台账**。

## 2. 统计需求如何被数据支撑

### 2.1 「有多少张 RTX5090 卡？」

| 步骤 | 数据 |
|------|------|
| 台账 | 产品「RTX 5090 算力服务器」下 quantity=150 |
| 部件 | kind=`accelerator`, model=`RTX5090`, qty_per_unit=6 |
| 大屏/API | `accelerator_totals`: `{ label:"RTX5090", count:900, unit:"张" }` |

加昇腾：新产品 + 台账 80 台 + 部件 `Ascend910B ×8` → 大屏多一行「Ascend910B · 640 张」。

### 2.2 「有多少块硬盘？各规格多少？」

| 步骤 | 数据 |
|------|------|
| 台账 | 存储服务器 quantity=388 |
| 部件 | kind=`disk`, model=`HC320`, capacity=`8TB`, qty_per_unit=36 |
| 大屏/API | `disk_totals`: `{ label:"HC320 · 8TB", count:13968, unit:"块" }` |

若同机混插两种盘：同一台账下挂 **两行** disk 部件即可分别汇总。

### 2.3 容量 / 估算算力

- **PB**：Σ(台数 × 单台盘数 × 单盘 TB) / 1024（二进制近似，可配置）  
- **MW**：Σ(卡总数 × 每卡兆瓦系数)；系数表按 model 配置（5090/4090/昇腾可不同）  
禁止再靠 brand 字符串硬猜。

## 3. 场景：加「华为昇腾 910B」

1. **新增产品**：名称、编码、**类别=算力**、备注、排序  
2. **添加台账**：品牌 `Ascend910B`、数量、状态、机位、机箱参数…  
3. **部件**：accelerator / Ascend910B / 单台张数（如 8）  
4. **大屏**：总台数+；算力小字+；卡数统计出现 Ascend910B；产品构成多一块；状态柱对应增加  

错误：挂到 5090 产品下或只把「昇腾×8」写进扩展文本而不建部件 → **卡数统计不到**。

## 4. 维护表单（简单、关联强）

### 4.1 产品表单（顺序）

1. 名称（必填）  
2. 编码（必填，唯一）  
3. **类别**（必填，下拉：算力 / 存储，默认算力）  
4. 备注  
5. 排序（默认 0）  

### 4.2 台账表单（顺序）

**身份区（关联产品已选定）：**  
品牌短码 → 资产编码 → 机位 → 状态（默认待上架）→ 数量（默认 0）→ 单位（默认台）→ 排序  

**机箱参数区：** 机箱 → 主板 → 内存 → 接口 → 扩展说明 → 电源 → 光模块 → 附加键值行  

**部件区（统计核心，表格行编辑）：**  

| 类型 | 型号 | 容量（仅硬盘） | 单台数量 |
|------|------|----------------|----------|
| 加速卡 / 硬盘 | RTX5090 | 8TB | 6 |

- 类别为算力时，默认提示可加一行加速卡；存储默认提示加硬盘行  
- 单台数量 ≥ 1；型号必填  
- 保存时整单替换该台账部件列表（事务内）

### 4.3 主表 / 展开表

- 主表：产品、类别、品牌汇总、整机总数、操作（添加台账/编辑/删除）  
- 展开：品牌、关键参数摘要、**卡/盘摘要**（如 `RTX5090×6`）、数量、状态、机位、操作  
- 工具条：搜索 | 状态 | **导入** | **导出** | **新增产品**（右侧）

### 4.4 导入 / 导出

- **导出** CSV（UTF-8 BOM）：一行一个「台账×部件」；无部件时部件列为空仍导出台账  
- **导入**：按 `product_code` 匹配或创建产品；按 brand+location+asset 更新/插入台账；部件列非空则重建部件  
- 权限：仅 admin；导出可登录后下载  

CSV 列（稳定契约，中文表头）：

`产品名称,产品编码,类别,品牌短码,状态,数量,单位,机位,资产编码,机箱,主板,内存,接口,扩展,电源,光模块,其他参数,部件类型,部件型号,容量,单台数量`

类别取值：算力 / 存储；部件类型取值：加速卡 / 硬盘。

## 5. 大屏（极简 + 充分统计）

**原则：** 白底、少装饰、玻璃轻量；每个统计维度只出现一次。

| 顺序 | 区块 | 内容 | 数据来源 |
|------|------|------|----------|
| 1 | 顶栏 | 标题、机房、时钟、刷新时刻、维护 | site + 客户端 |
| 2 | 主统计 | **设备总台数** + 小字算力/存储台数 | category 汇总 |
| 3 | 部件统计 | **加速卡**按型号张数；**硬盘**按「型号·容量」块数 | components 聚合 |
| 4 | 侧指标 | 存储 PB、估算 MW（一行弱化） | 公式基于部件 |
| 5 | 双图 | 产品构成（整机）｜运行状态（整机） | 不重复卡/盘占比 |
| 6 | 明细表 | 产品、品牌、状态、整机数、卡/盘摘要、机位 | devices + components |

禁止：多套整机占比图；把卡数再做成第三张饼图与部件条重复。

## 6. API 要点

- `GET /api/dashboard` 增加 `accelerator_totals[]`、`disk_totals[]`；`stats` 按 `category` 汇总  
- `GoodsModel` 增加 `components[]`  
- `ProductModel` 增加 `category`  
- `GET /api/inventory/export` → CSV 文本  
- `POST /api/inventory/import` → `{ csv }` 或 raw body
