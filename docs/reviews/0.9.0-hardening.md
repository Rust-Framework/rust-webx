# rust-webx 0.9.0 加固台账（对抗评审 → 版本落地）

> 目标：把 0.8.0 对抗评审发现的 23 条缺陷与 6 个体系性设计问题在 0.9.0 前收敛，
> 先做行为修复（0.8.1 语义），再做 API 收口（0.9 breaking），最后发布 0.9.0。
> 本文件是跨轮次的唯一进度来源；每轮结束时更新状态并记录验证命令。

## 判据（第一性原理不变量）

| # | 不变量 |
|---|---|
| I1 | 单一真相源：一次请求内“操作者 / 失败原因”只有一个权威表示 |
| I2 | 不可伪造：身份只来自认证层；显式标记只从声明来源取值 |
| I3 | 状态可区分：401 / 403 / 400 在类型与响应上可区分 |
| I4 | 类型语义一一对应：`Option`=可缺失、`Some([])` 可表达、非法值必 400 |
| I5 | 默认 fail-closed：忘记写代码时的默认行为必须是拒绝/安全 |
| I6 | 声明即契约：宏/元数据/运行时/OpenAPI 同源 |
| I7 | 生命周期可证明：先就绪再收流量、先排空再停依赖；扩展点可组合 |
| I8 | 错误可归因且不泄漏：5xx 不把内部文本写给客户端；错误路径不被跳过 |

## 轮次日志

### Round 1（release/0.9.0 分支首次提交）

完成：#6、#7、#9、#12、#17、#23；#1、#10、#22 部分。

- 401 单一出口：`problem_response::write_unauthorized` + `server::write_framework_error`
  + `Error::public_detail()`；endpoint 不再自己写 401；JWT 解码细节只进日志。
- 5xx 脱敏：`Error` 内部变体不再进 `detail`；文件下载/range seek 失败同样脱敏。
- 限流：`IHttpRequest::remote_addr`（默认 `None`）+ host accept 记录对端地址 +
  `Retry-After`；拿不到地址时跳过而非全局同桶。
- 绑定：删 `claims` 魔名、`r#` unraw、claim raw-first、`Option<复合>` 400、
  `?ids=` → `Some([])`。
- 管道：`after` 钩子在 `Err` 路径也执行（metrics/tracing 能看到 5xx）。
- 文档：parameter-binding（claims/复合/Option<Vec>）、jwt-authentication（401 挑战）、
  authorize-macro（401 挑战）、caching-rate-limit（对端地址/Retry-After）、CHANGELOG Unreleased。

验证：`cargo test -p rust-webx-host`、`cargo test -p rust-webx --test auth_integration_test
--test binding_test --test binding_requiredness_test`、`cargo test -p rust-webx-macros --lib`
（20 passed）、`cargo test -p rust-webx-core --lib`（23 passed）全绿。

### Round 2（release/0.9.0 第二次提交）

完成：#2、#3、#8、#10、#22；#20、#5 部分；#11 由并行任务实现。

- 生命周期：`run()`/`run_at()` 先绑定全部 listener 再启动任何东西；绑定失败返回 `Err`
  （进程非 0 退出）；listener 任务 panic 通过 JoinError 传播；启动失败逆序回滚已启动
  HostedService；`stop` 逆序 + 30s 超时；Ctrl+C 改为进程级注册表（多 Host 各自可停）。
- 停机：`Notify` → `watch`（`send_replace` 存值，早于 accept 循环的 shutdown 不再丢失）；
  每连接 `graceful_shutdown()`，排空窗口后不再直接 abort。
- SPA：`index.html` 回退移到路由未命中之后（`SpaMiddleware::try_index_fallback`），
  仅 `Accept: text/html` 的 GET/HEAD 生效；`/api/*` 与数据客户端得到 404；API JSON 不再
  继承 `Cache-Control: public`。
- 管道：413 由 `IHttpContext::take_early_error` 记录、在管道内抛出，CORS/安全头/日志/指标可见。
- 错误模型：新增 `ResponseSerialization`(500) 与 `State`(500)；`public_detail()` 不外泄；
  host body 状态机错误从 `Error::Http` 迁移到 `State`。
- APP_ENV：未设置/非法值 warn-once（默认值翻转留待发布轮）。
- 文档：hosted-services（逆序 stop/回滚/超时）、graceful-shutdown（watch/排空/超时）、
  ecosystem-overview（SPA 回退语义）、CHANGELOG。
- 测试：新增 [hardening_test.rs](../../crates/host/tests/hardening_test.rs)（5 例：SPA 回退矩阵、
  API 缓存头、413 过 CORS、绑定冲突报错、early shutdown 不丢）；宏单测 20→25、openapi 4→7、
  binding_requiredness +1（derive→spec 端到端断言 body 字段）。

验证：`cargo test -p rust-webx-host` 全绿（含 hardening_test 5 passed）、
`cargo test -p rust-webx-core`（32 lib + 全 target）、`cargo check --workspace --all-targets`。

已知遗留（Round 3 处理）：`upload_download_test::resumable_download_reassembles_the_file`
依赖同二进制内其他测试先初始化静态 `DOWNLOAD_DIR`，单独运行会失败（既有测试隔离缺陷）。

### Round 3（release/0.9.0 第三次提交：身份单一真相源 D1）

完成：#13、#14、#15。

- **单一真相源**：`RequestContext` 的 task-local 从 `Option<String>`（只有 sub）升级为
  `Option<Arc<IdentityUser>>`；HTTP dispatch 在 `RequestModel::bind` **之前**建立上下文，
  于是 binder、Handler、审计 helper、持久层读同一份身份；`operator_id()` 保持兼容
  （`identity().map(|u| u.id.clone())`）。后台任务/HostedService 默认无身份（System），
  需要时显式 `RequestContext::run(Some(identity), ...)`。
- **fail-closed 匿名**：`Option<IdentityUser>` 必须写 `#[fromclaim(optional)]`；裸
  `#[fromclaim]` 编译失败并给出修复文案；`optional` 用于 required 身份/普通 claim 各有
  明确错误；一个请求只能有一个身份字段（多身份编译错误）。
- **表达力收口**：`IdentityUser::{tenant, require_tenant}`（空串=无 tenant claim，
  403 而非 401）；`RequestUser::{permissions, has_permission, require_role, require_tenant}`
  区分 401（匿名）/403（已认证但缺角色或租户）。
- 文档：`user-identity.md` 新增 RequestUser trait 表与「基础设施层同一份身份」章节、
  匿名为必须显式声明；update 5 处旧口径 + 两个 README；CHANGELOG 增加 Breaking/Added。
- 测试：core 42 passed（+10）、macros 32 passed（+8，含 fail-closed 全矩阵）、
  webx binding 21/26、`cargo check --workspace --all-targets` 通过。

### Round 4（release/0.9.0 第四次提交）

完成：#5、#16、#18、#19；并清理测试隔离 flake。

- **安全默认**：`APP_ENV` 未设置/非法时默认 `Production`（原 Development），弱 JWT secret /
  CORS `*` 等守卫因此默认生效；本机开发须显式 `APP_ENV=Development`（warn-once 提示）。
  全部测试宿主改为显式 Development（`production_guard_test` 保持故意 Production）。
- **无效 token 降级**：坏/过期 token = 未认证，不再拒绝整个请求；公开端点（登录/健康/配置）
  带旧 token 仍可用，受保护端点由 `#[authorize]`/身份字段统一 401 + 挑战头。
- **HTTP 方法语义**：405 携带 `Allow`；plain `OPTIONS` 对已知路径返回 204 + `Allow`、
  未知路径 404；只有真正的 CORS 预检（`Origin` + `Access-Control-Request-Method`）短路。
- **OpenAPI 键**：`RouteEntry`/`RequestParamEntry` 增加 `TypeId`，OpenAPI 以 TypeId 优先、
  字符串回退；限定路径与跨 crate 同名 Request 不再丢参数/串台。
- **测试隔离**：`upload_download_test` 去掉进程级静态目录，改为每测试唯一临时目录 +
  DI 注入；补跑两次 + 单跑两条用例验证。
- 新增回归测试：`method_options_test`（5：405 Allow、plain OPTIONS 204/404、preflight、
  正常 GET+CORS）、`protocol_test` 公开端点坏 token→200 / 受保护→401+挑战、
  cors_test plain OPTIONS 不短路、openapi TypeId 两条、webx 端到端限定路径。
- 测试计数：core 44、host 155、webx 107、openapi 9、macros 32；`cargo check --workspace
  --all-targets` 通过；scoped clippy `-D warnings` 0 warning。

### Round 5（release/0.9.0 第五次提交）

完成：#1 剩余、#4、#20 剩余、#21；并补 0.9 迁移文档。

- **中间件槽位**：`MiddlewareSlot::{BeforeCors, AfterAuth, AfterSpa}` +
  `use_middleware_at` / `use_middleware_with_at`；默认槽改为 **AfterAuth**，框架自带
  `RequestTracing` 因此能记录真实用户；管道顺序调整为
  SecurityHeaders → RequestId → user(BeforeCors) → CORS → Metrics → RateLimit → auth →
  user(AfterAuth) → SPA → user(AfterSpa) → Router（429/413 带 CORS 头、429 计入指标）。
- **HostedService scope**：`DispatchRuntime::run_in_scope` 为每次 `start`/`stop` 创建独立
  DI scope，`dispatch_provider()` 优先返回 scope provider，Scoped 依赖（DbContext/连接）
  随调用结束释放，不再落 root 变成进程级单例；核心单测证明同 scope 缓存复用、跨 scope 隔离。
- **`add_pipeline_with`**：`IPipelineBehavior` 构造期拿到 resolver（文档固化 rust-dix 构建期
  校验下唯一可移植写法 `get_any(type_name)+downcast`，或闭包捕获 Arc）；短路返回错误类型的
  错误信息含期望类型与修复建议。
- **限流可信代理**：`RateLimit.TrustedProxies` CIDR 列表；只有直连对端属于可信代理才采信
  `X-Forwarded-For`，客户端 IP 取最右侧非可信 hop；`TrustProxy=true` 但列表为空时忽略转发头
  并 warn（防伪造）。
- **文档**：新增 `16-migration/upgrade-to-0.9.md`（Breaking + 行为变化 + 检查清单）并更新
  `16-migration/INDEX.md` / `INDEX.json`；`07-middleware/{ordering-strategy,custom-middleware}`、
  `06-di-lifecycle/hosted-services`、`11-production/caching-rate-limit` 同步。
- 测试：新增 `middleware_slots_test`（3：默认槽读身份、匿名仍运行、BeforeCors 短路早于 CORS）、
  core `run_in_scope` 2 例、rate-limit CIDR/XFF 2 例、pipeline 构造注入 2 + 错误文案 2。
- 计数：core 48、host 162、webx 107、openapi 9、macros 32。
