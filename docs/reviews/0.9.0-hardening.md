# rust-webx 0.9.0 加固台账（对抗评审 → 版本落地）

> 目标：把 0.8.0 对抗评审发现的 23 条缺陷与 6 个体系性设计问题在 0.9.0 前收敛，
> 先做行为修复（0.8.1 语义），再做 API 收口（0.9 breaking），最后发布 0.9.0。
> 本文件是跨轮次的唯一进度来源；每轮结束时更新状态并记录验证命令。

## 判据（第一性原理不变量）

| # | 不变量 |
|---|---|
| I1 | 单一真相源：一次请求内“操作者 / 失败原因”只有一个权威表示 |
| I2 | 不可伪造：身份只来自认证层；显式标记只从声明来源取值 |
| I3 | 状态可区分：401 / 403 / 400 在类型与响应上可区分 |
| I4 | 类型语义一一对应：`Option`=可缺失、`Some([])` 可表达、非法值必 400 |
| I5 | 默认 fail-closed：忘记写代码时的默认行为必须是拒绝/安全 |
| I6 | 声明即契约：宏/元数据/运行时/OpenAPI 同源 |
| I7 | 生命周期可证明：先就绪再收流量、先排空再停依赖；扩展点可组合 |
| I8 | 错误可归因且不泄漏：5xx 不把内部文本写给客户端；错误路径不被跳过 |

## 轮次日志

### Round 1（release/0.9.0 分支首次提交）

完成：#6、#7、#9、#12、#17、#23；#1、#10、#22 部分。

- 401 单一出口：`problem_response::write_unauthorized` + `server::write_framework_error`
  + `Error::public_detail()`；endpoint 不再自己写 401；JWT 解码细节只进日志。
- 5xx 脱敏：`Error` 内部变体不再进 `detail`；文件下载/range seek 失败同样脱敏。
- 限流：`IHttpRequest::remote_addr`（默认 `None`）+ host accept 记录对端地址 +
  `Retry-After`；拿不到地址时跳过而非全局同桶。
- 绑定：删 `claims` 魔名、`r#` unraw、claim raw-first、`Option<复合>` 400、
  `?ids=` → `Some([])`。
- 管道：`after` 钩子在 `Err` 路径也执行（metrics/tracing 能看到 5xx）。
- 文档：parameter-binding（claims/复合/Option<Vec>）、jwt-authentication（401 挑战）、
  authorize-macro（401 挑战）、caching-rate-limit（对端地址/Retry-After）、CHANGELOG Unreleased。

验证：`cargo test -p rust-webx-host`、`cargo test -p rust-webx --test auth_integration_test
--test binding_test --test binding_requiredness_test`、`cargo test -p rust-webx-macros --lib`
（20 passed）、`cargo test -p rust-webx-core --lib`（23 passed）全绿。

### Round 2（release/0.9.0 第二次提交）

完成：#2、#3、#8、#10、#22；#20、#5 部分；#11 由并行任务实现。

- 生命周期：`run()`/`run_at()` 先绑定全部 listener 再启动任何东西；绑定失败返回 `Err`
  （进程非 0 退出）；listener 任务 panic 通过 JoinError 传播；启动失败逆序回滚已启动
  HostedService；`stop` 逆序 + 30s 超时；Ctrl+C 改为进程级注册表（多 Host 各自可停）。
- 停机：`Notify` → `watch`（`send_replace` 存值，早于 accept 循环的 shutdown 不再丢失）；
  每连接 `graceful_shutdown()`，排空窗口后不再直接 abort。
- SPA：`index.html` 回退移到路由未命中之后（`SpaMiddleware::try_index_fallback`），
  仅 `Accept: text/html` 的 GET/HEAD 生效；`/api/*` 与数据客户端得到 404；API JSON 不再
  继承 `Cache-Control: public`。
- 管道：413 由 `IHttpContext::take_early_error` 记录、在管道内抛出，CORS/安全头/日志/指标可见。
- 错误模型：新增 `ResponseSerialization`(500) 与 `State`(500)；`public_detail()` 不外泄；
  host body 状态机错误从 `Error::Http` 迁移到 `State`。
- APP_ENV：未设置/非法值 warn-once（默认值翻转留待发布轮）。
- 文档：hosted-services（逆序 stop/回滚/超时）、graceful-shutdown（watch/排空/超时）、
  ecosystem-overview（SPA 回退语义）、CHANGELOG。
- 测试：新增 [hardening_test.rs](../../crates/host/tests/hardening_test.rs)（5 例：SPA 回退矩阵、
  API 缓存头、413 过 CORS、绑定冲突报错、early shutdown 不丢）；宏单测 20→25、openapi 4→7、
  binding_requiredness +1（derive→spec 端到端断言 body 字段）。

验证：`cargo test -p rust-webx-host` 全绿（含 hardening_test 5 passed）、
`cargo test -p rust-webx-core`（32 lib + 全 target）、`cargo check --workspace --all-targets`。

已知遗留（Round 3 处理）：`upload_download_test::resumable_download_reassembles_the_file`
依赖同二进制内其他测试先初始化静态 `DOWNLOAD_DIR`，单独运行会失败（既有测试隔离缺陷）。

### Round 2 额外发现（构建期熵，已先行修复）

- docbit-host 的 build script 用 brotli **quality 11** 压缩 `docbit/wwwroot`（576 文件 / 27MB），
  全新构建单线程超过 1 小时，直接把 `cargo test --workspace` 卡死。已改为默认 quality 9 +
  `WEBX_BROTLI_QUALITY` 环境变量覆盖（0-11）+ `rerun-if-env-changed`，并在 CHANGELOG 记录。
- 另发现 `docbit/wwwroot` 内 `lute.min.js` 等 vendor 文件存在重复副本（各 3.62MB），
  Round 3+ 评估去重/瘦身，减少嵌入体积与构建时间。
