# 写作风格与格式规范

跨项目通用规则。**项目专属约定**一律从当前书 `FOREWORD.md` 的「约定与符号」读取（见 [project-bootstrap.md](project-bootstrap.md)）。

## 语言与受众

- 默认正文：**简体中文**（以 FOREWORD 或 `INDEX.json` `meta.language` 为准）
- 受众：使用该框架/库的开发者
- 语气：直接、工程化；解释设计意图
- 标识符保持源码语言：`TypeName`、`#[macro]`、函数名

## 符号与约定（默认 + 项目覆盖）

| 约定 | 默认 | 项目覆盖来源 |
|------|------|-------------|
| 代码统一导入 | 自 FOREWORD 读取 | `FOREWORD.md` |
| 推荐 / 反模式 | `✅` / `❌` | FOREWORD |
| 路径参数占位 | `{id}` 等 | 路由/API 文档约定 |
| 示例项目 | 自 Profile | FOREWORD、quickstart |
| 验证命令 | 自 Profile | `docs/README.md` |

**禁止**在未读 FOREWORD 时使用其他项目的 import 行或 crate 名。

## Markdown 结构

### 标题

- 小节：单个 `#`（与 section title 一致或略具体）
- `##` 逻辑块；`###` 步骤或子话题
- 不超过四级

### 必备结尾

```markdown
## 小结

{1–3 句}

下一节：[标题](next-section.md)
```

跨章：`下一章：[标题](../NN-chapter/INDEX.md)`  
章末最后一节可用「本章完结」。

### 表格

对比、职责、字段、读者画像、难度。

### 代码块

- 标注语言：`rust`、`typescript`、`json`、`bash`、`mermaid` 等
- 教程：**先完整可运行**，再拆片段
- 分步注释格式与项目既有小节保持一致（如 `// ── 第一步 ──`）
- 片段用 `...` 省略；示例须与**当前仓库** API 一致

### 图示

- 流程/架构：**mermaid**
- 简单层级：ASCII 块
- 一图一义

### 链接

- 章内：`[标题](section-id.md)`
- 跨章：`[标题](../other-chapter/section-id.md)`
- 锚文字用标题，不用「点击这里」

## 小节模板

### A. 教程小节

```markdown
# {标题}

## 完整代码
...

## {概念}解读
### 第一步：...
| 元素 | 含义 |

## 背后发生了什么
{mermaid 可选}

## 常见变体

## 小结
下一节：[...](...)
```

### B. 概念小节

```markdown
# {标题}

## {概念}是什么
...

## {原则/对比}
{表或图}

## {框架}边界
### 负责 / 应用负责 / 不内置

## 小结
下一节：[...](...)
```

### C. 章 INDEX

```markdown
# 第 N 章 {标题}
{导语}
## 本章小节
| 小节 | 内容 |
## 学习目标（可选）
## 下一步
```

## 开发者指南 vs API 手册

| 指南（本书） | API 手册 |
|-------------|---------|
| 何时用、如何组合 | 穷举签名 |
| 约定与反模式 | 参数列表 |
| 可运行示例 | 碎片 snippet |
| 链到他章 / rustdoc | 单页堆类型 |

API 大全 → 项目 rustdoc 或 dedicated reference；书籍保持指南形态。

## 禁止

- 未实现能力写「已支持」
- 使用其他项目的 API / crate 名
- 无小结、无导航的孤立小节
- 大段复制他节（应链接）
- 书籍正文语言与 FOREWORD 声明不一致

## 修订现有文档

1. 匹配同章既有模板与语气
2. 披露顺序变化 → 同步章 INDEX 顺序与 `INDEX.json`
3. 检查 inbound「下一节」链接
