# rust-webx 1.0 规划与执行（rust-dix 0.10 / rust-ef 2.1 基线）

> 状态：执行中（2026-11-11 更新）。0.10.0 已发布；本文件是 1.0.0 的唯一执行计划，
> 同时记录本轮依赖同步与探针证据。

## 0. 现状摘要（本轮实测）

- **依赖已同步到最新**：`rust-dix` / `rust-dix-macros` **0.10.0**，
  `rust-ef` / `rust-ef-sqlite` / `rust-ef-mysql` **2.1.0**（rust-ef 2.1.0 依赖 rust-dix 0.10，
  `Cargo.lock` 中 rust-dix 只剩单一 0.10.0）。
- **编译基线**：`cargo check --workspace --all-targets` **0 error**，rust-webx 源码零改动。
- **测试基线**：`cargo test --workspace --no-fail-fast` 仅 **1 个失败**
  （`dispatch_runtime::tests::scope_provider_does_not_leak_outside_run_in_scope`：
  rust-dix 0.8+ 默认严格 scope 校验后 root 解析 Scoped 返回 `Err(ScopedFromRootProvider)`）。
  本轮已按严格语义改写该测试，`rust-webx-core` **51/51** 绿。
- **rust-ef 2.1 能力**：`add_dbcontext` / `add_dbcontext_async` / `add_dbcontext_keyed` /
  `add_dbcontext_anykey`、`DbContextKey`（typed key，生成 `From<Key> for ServiceKey`）、
  `get_owned_context`、`DbContextResolver`；DI 集成面收敛在 `rust_ef::di`。
- **1.0 目标**：生产级发布。核心不是「再修几个 bug」，而是**把 rust-webx 中所有可由
  rust-dix 提供的能力交回 dix**，删掉自建影子（ambient scope 传播、重复的 DI 封装、兼容层），
  再完成严格 scope / dispose / async / 文档 / 示例 / 发布。

## 2. 架构原则：能用 dix 就不自建（1.0 重构主线）

audit 结论：rust-webx 目前有一处**自建 DI 影子**——`dispacth_runtime` 的 task-local
`ACTIVE_RUNTIME` / `ACTIVE_SCOPE_PROVIDER` + `dispatch_provider()` / `dispatch_handler_cache()`
+ `DispatchRuntime::run_in_scope()`。它模拟的正是 rust-dix 已经提供的：
scope 生命周期、`ScopeFactory`、provider 注入、scoped 解析语义。1.0 将其删除，改为显式依赖传递：
**dix 是唯一 DI 真相源，rust-webx 只保留 dix 无法提供的框架能力**
（HTTP 路由/绑定、中间件管道、错误模型、inventory 注册表、Host 生命周期）。

### R1 删除 ambient DI（core / host / mediator / tests / examples）

- `DispatchRuntime` 退化为 Host 的**显式句柄**（`provider: Arc<ServiceProvider>` +
  `handler_cache: Arc<HandlerCache>`），**不再有 task-local 与 `run/run_in_scope`**。
- `Mediator` 持有 `Arc<HandlerCache>`（`Host::build` 时以 instance/闭包捕获方式提供），
  `mediator::dispatch(provider, cache, req)` 显式接收 cache；删除 `dispatch_handler_cache()`。
- `IHostedService` 签名改为显式 DI 句柄：
  ```rust
  #[async_trait]
  pub trait IHostedService: Send + Sync {
      async fn start(&self, services: Arc<dyn ScopeFactory>) -> Result<()>;
      async fn stop(&self, services: Arc<dyn ScopeFactory>) -> Result<()>;
  }
  ```
  后台任务需要 scoped 依赖时显式 `let scope = services.create_scope(); let ctx = scope.get_owned::<T>()?;`
  —— 与 `rust-dix`/MEDI 的 `IServiceScopeFactory` 模型一致，删除 `run_in_scope` 包装。
- HTTP 请求路径使用 Host 的 runtime 句柄与请求级 scope（已有），不依赖 ambient。
- `grep -R "dispatch_provider|dispatch_handler_cache|ACTIVE_RUNTIME|ACTIVE_SCOPE_PROVIDER|run_in_scope" crates/`
  必须为 0（迁移文档除外）。

### R2 严格 scope 默认 + 显式宽松逃生门

- `HostBuilder::try_build()`：`build_with(ServiceProviderOptions::default())`（strict）；
- 新增 `HostBuilder::lenient_scope_validation()`（`ServiceProviderOptions::lenient()`，
  仅迁移期，文档标注 deprecated 计划）；
- `try_build_async()` / `build_async_with` 支持 async singleton（如 `add_dbcontext_async`）；
- `RdiError` → `webx::Error` 映射：`ScopedFromRootProvider` 给出 `provider.scope()` /
  `get_owned()` / `run_in_scope` 替代方案的提示；`ProviderDisposed`/`ScopeDisposed` 映射为
  `Error::Di`（文案可操作）。

### R3 框架默认注册改 `try_add*`

rust-dix 0.8 起 single-service 解析「后注册优先」，框架内置默认若用 `singleton` 注册会**覆盖用户
先注册的实现**。以下默认注册改 `try_add*`（存在即不覆盖），并加回归测试：
- `Host` 内置：`IStringLocalizer`、`IEndpointCatalog`、`HealthRegistry`（instance → try_add 等价：
  先 `is_registered` 判断或 `try_add_singleton` 包装）；
- `add_mediator` / `add_middleware` / `add_hosted_service` / `add_typed_pipeline*` / `add_pipeline*`。
- 回归：用户先注册 → 框架后注册 → 解析到用户实现。

### R4 生命周期：把 dispose 交回 dix

- Host 停机顺序：停止接受新请求 → 停 hosted services（新签名）→ 等待连接 drain →
  **`provider.dispose()`**（逆序释放 singleton、执行 cleanup、清 named）。
- 测试：disposable singleton 逆序释放、cleanup 逆序、`dispose()` 幂等、dispose 后
  `dispatch`/`Mediator` 返回 `ProviderDisposed` 的可读错误；`DispatchRuntime` 不阻止 dispose
  （provider Arc 在 Host 与 runtime 间共享，dispose 后所有解析返回 typed error）。
- `Scope` 的 `Drop`/`dispose` 已由 dix 负责，框架不再自建释放逻辑。

### R5 采纳 dix 新能力（避免重复造轮子）

- `Arc<dyn ScopeFactory>`：hosted services / 后台 worker 的显式 scope 来源（R1 已用）；
  文档示例统一用它，而非 `dispatch_provider()`。
- `is_registered::<T>()`：可选特性探测（localizer / health / catalog / mediator 只在已注册时启用）。
- `get_all_keyed`：若 1.0 增加 keyed middleware/hosted/behavior 注册 API，收集 side 用
  `get_all_keyed`；否则文档说明「keyed 注册不参与 get_all」。
- typed `ServiceKey`：框架的 keyed 扩展 API 采用 `impl Into<ServiceKey>`，遵循
  `From<LocalKey> for ServiceKey` 官方扩展契约，不复制注入宏。
- `IProvider` / named services / `ServiceProviderWrapper`：re-export 或在文档给出插件/多租户用法，
  不在框架内另造抽象。
- async：`HostBuilder::try_build_async()` + rust-ef `add_dbcontext_async` 端到端示例。

### R6 1.0 breaking 清理（与 rust-dix 0.10 升级同批）

- 删除 `IErasedPipelineBehavior` + `add_pipeline`/`add_pipeline_with` + erased↔typed 桥
  （`crates/core/src/pipeline.rs`、`crates/core/src/route/ext.rs`、`mediator/dispatch.rs`），
  dispatch 简化为单 typed 链；
- 删除 `register_handlers!`（0.2 deprecated，`crates/webx/src/lib.rs`）；
- 删除 `build_resource_policy_from_routes`（0.6 deprecated，`crates/host/src/authz.rs`）；
- 清理 `#[allow(deprecated)]` 与迁移测试；
- `16-migration/upgrade-to-1.0.md`（中英）给出 before/after 与 grep 清单。

### R7 示例与构建体积

- docbit/dmbit 升级到 rust-ef 2.1 API：`add_dbcontext`（strict scope 下 hosted service 用
  `ScopeFactory` 显式 scope）；可评估 `add_dbcontext_async` + `try_build_async`；
  `docbit/host/examples/scope_smoke.rs` 按 2.1 重写；
- `docbit/wwwroot` vendor 重复文件（`lute.min.js` 等 3.62MB 级重复副本）去重/瘦身，
  降低嵌入体积与 brotli 构建时间。

### R8 文档 / 技能 / 发布

- 手册依赖注入章节按 rust-dix 0.10 重写（strict/lenient、ScopeFactory、dispose、typed keys、
  async build、`#[inject]` on impl、`RdiError` 目录）；
- `upgrade-to-1.0.md` 中英；`rust-xazgo-dix` 技能 0.7→0.10；`rust-xazgo-webx`/`rust-xazgo-ef`
  版本矩阵同步 1.0；

## 6. 决策记录

- **D1**：0.8→0.10 升级与全部 breaking 合并为 **1.0.0** 一次发布（0.10.x 只做非 breaking 修复）。
- **D2**：默认 **strict scope**；`lenient_scope_validation()` 为显式迁移逃生门。
- **D3**：**删除 ambient DI**（`dispatch_provider`/`run_in_scope`/task-local），改为
  `ScopeFactory` 显式注入与显式 scope 传递；这是 1.0 最重要的架构清理。
- **D4**：不保留双版本 rust-dix / 兼容层；rust-ef 2.1 已对齐 0.10。
- **D5**：框架只保留 dix 无法提供的能力（HTTP 路由/绑定/中间件/错误模型/inventory 注册表/Host 生命周期）。
- **D6**：async DI 通过 `try_build_async` 暴露；Host 入口默认仍 `try_build`，async 是显式选择。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 删除 ambient DI 是用户可见 breaking | 旧代码 `dispatch_provider()` 编译失败 | `upgrade-to-1.0` 明确迁移：hosted service 用 `ScopeFactory`；handler 用 `#[inject(owned)]`；`Host` 句柄显式传递 |
| strict scope 破坏既有 root 解析 | 启动/请求期报 `ScopedFromRootProvider` | lenient 逃生门 + 错误文案给替代写法；0.10.x 文档预告 |
| dispose 与 `Arc<ServiceProvider>` 共享 | 停机后残留解析 | 停机序列固定顺序；dispose 后 typed error 测试；文档禁止 dispose 后 dispatch |
| async build 引入启动失败面 | 启动错误映射 | `try_build_async -> Result<Host, Error>`，`RdiError` 文案透传 |
| vendor 重复资产 | 体积/构建时间 | R7 去重 + brotli 质量复核 |
