| 决策点 | 选择 | 理由 |
|---|---|---|
| P0-3 IPipelineBehavior 签名 | 移除 `svc` 参数，纯 MediatR 模式 | Behavior 通过构造注入获取依赖（Singleton 注册），trait 最简洁，无需适配器 |

```rust
//! Pipeline behavior chain construction.

use std::sync::Arc;
use crate::pipeline::{BoxedNextFn, IPipelineBehavior};

/// Build a chain of pipeline behaviors wrapping a terminal handler.
///
/// Behaviors are applied in Vec order: first element is outermost
/// (runs first on request, last on response). Reverse-fold constructs
/// the nested closure chain.
pub(crate) fn build_chain(
    behaviors: Vec<Arc<dyn IPipelineBehavior>>,
    terminal: BoxedNextFn,
) -> BoxedNextFn {
    let mut next = terminal;
    for behavior in behaviors.into_iter().rev() {
        let inner_next = next;
        let b = Arc::clone(&behavior);
        next = Box::new(
            move |req: Box<dyn std::any::Any + Send>| -> crate::pipeline::BoxedPipelineFuture {
                Box::pin(async move { b.handle(req, inner_next).await })
            },
        );
    }
    next
}
```

#### 改动 3：Mediator::send 插入行为链

**文件**：[crates/core/src/mediator/default.rs](file:///e:/GitCode/RF/rust-webx/crates/core/src/mediator/default.rs)

**改动内容**：在 P0-5 改造基础上，`send` 方法插入行为链解析。核心思路：**handler 在 build chain 前解析**，scope 生命周期与 chain 解耦：

```rust
async fn send<T, R>(&self, req: T) -> Result<R>
where
    T: IRequest<R> + Send + 'static,
    R: serde::Serialize + Send + 'static,
{
    let cache = HandlerCache::get_or_init();
    let full_name = std::any::type_name::<T>();
    let entry = cache.get(full_name).or_else(|| {
        let short = full_name.rsplit("::").next().unwrap_or(full_name);
        cache.get(short)
    }).ok_or_else(|| Error::Di(...))?;

    // 创建 per-call scope（P0-5 已完成）
    let scope = self.provider.create_scope();
    let resolver: &dyn IServiceResolver = &scope;

    // 在 scope 存活期间解析 handler（factory 借用 scope，返回 owned handler）
    let handler = (entry.factory)(resolver);

    // 从 scope 收集所有 IPipelineBehavior 注册（Singleton 注册，Arc 克隆）
    let behaviors: Vec<Arc<dyn IPipelineBehavior>> = scope.get_all::<dyn IPipelineBehavior>();

    // 终端闭包：捕获 owned handler + entry.call，scope 已不再需要
    let entry_call = entry.call;
    let terminal: BoxedNextFn = Box::new(
        move |req: Box<dyn std::any::Any + Send>| -> BoxedPipelineFuture {
            Box::pin(async move { (entry_call)(handler, req).await })
        },
    );

    // 构造行为链（空 behaviors 时直接返回 terminal）
    let chain = crate::mediator::pipeline::build_chain(behaviors, terminal);

    // 执行链
    let result_box = chain(Box::new(req)).await?;
    let result = *result_box.downcast::<R>().expect("Response type mismatch");
    Ok(result)
}
```

**关键正确性**：
- handler 在 scope 存活期间解析，factory 借用 `&scope`，返回 owned handler（handler 持有 `Arc<T>` 克隆，scope 可释放）
- behaviors 是 `Vec<Arc<dyn IPipelineBehavior>>`，Arc 克隆保持存活
- terminal 闭包捕获 owned handler + 函数指针，全部 `'static`
- 空 behaviors 快速路径：`build_chain` 返回 terminal 原样

```rust
#[async_trait::async_trait]
pub trait IMiddleware: Send + Sync {
    /// Process an HTTP request (before hook).
    ///
    /// Return `Ok(ControlFlow::Continue(()))` to continue the pipeline,
    /// or `Ok(ControlFlow::Break(()))` to short-circuit (skip remaining
    /// middleware and the final handler; `after` hooks on already-executed
    /// middleware still run in reverse order).
    async fn invoke(&self, ctx: &mut dyn IHttpContext) -> Result<ControlFlow<()>>;

    async fn after(&self, _ctx: &mut dyn IHttpContext) -> Result<()> {
        Ok(())
    }
}
```

#### 改动 2：MiddlewarePipeline::execute 处理短路

**文件**：[crates/host/src/pipeline.rs](file:///e:/GitCode/RF/rust-webx/crates/host/src/pipeline.rs)

**改动内容**：`execute` 方法重写，跟踪已执行 middleware 并在短路时跳过 final_handler：

```rust
pub async fn execute(
    &self,
    ctx: &mut dyn IHttpContext,
    final_handler: HandlerFn,
) -> Result<()> {
    use std::ops::ControlFlow;

    let mut executed: Vec<Arc<dyn IMiddleware>> = Vec::new();
    let mut short_circuited = false;

    // Forward pass: invoke each middleware, track executed for after hooks
    for middleware in &self.middlewares {
        match middleware.invoke(ctx).await? {
            ControlFlow::Continue(()) => executed.push(Arc::clone(middleware)),
            ControlFlow::Break(()) => {
                short_circuited = true;
                break;
            }
        }
    }

    // Run final handler only if not short-circuited
    if !short_circuited {
        final_handler(ctx).await?;
    }

    // Reverse pass: after hooks on executed middleware only
    for middleware in executed.into_iter().rev() {
        middleware.after(ctx).await?;
    }

    Ok(())
}
```

            .lock()
            .map(|c| {
                c.iter()
                    .map(|(name, f)| {

                        HealthCheckEntry {
                            name: name.clone(),
                            status: s.status.to_string(),

                    .collect()
            })

    }

fn build_health_response(registry: &HealthCheckRegistry) -> serde_json::Value {
    let entries = registry.snapshot();
    let overall = if entries.is_empty() {
        "pass"
    } else if entries.iter().any(|e| e.status == "fail") {
        "fail"
    } else if entries.iter().any(|e| e.status == "warn") {
        "warn"
    } else {
        "pass"
    };
    serde_json::json!({
        "status": overall,
        "checks": entries
    })
}

## 假设与风险

### 假设

1. **IPipelineBehavior 无现有实现者**：该 trait 是新引入的，移除 `svc` 参数不会破坏任何现有代码。需通过 grep 验证 `impl IPipelineBehavior` 无匹配。
2. **StaticJsonEndpoint content_type 硬编码**：需检查 endpoint.rs，可能需新增 content_type 字段或新类型。
3. **HostBuilder 字段添加安全**：`health_registry` 是 `Arc<HealthCheckRegistry>`，`HealthCheckRegistry::new()` 返回 `Arc<Self>`，字段类型匹配。
4. **rust_dicore Scope 的 get_all 方法**：确认 `scope.get_all::<dyn IPipelineBehavior>()` 可用（已在 scope.rs L103 确认签名）。

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `IMiddleware::invoke` 签名变更破坏 docbit | docbit 若有自定义 middleware 会编译失败 | grep 确认 docbit 无 `impl IMiddleware`；若有则同步更新 |
| `StaticJsonEndpoint` 不支持自定义 content_type | 无法实现 `application/health+json` | 新增 `StaticHealthJsonEndpoint` 或扩展 `StaticJsonEndpoint` |
| 行为链 trait 简化后未来需要 svc 参数 | 后续若 behavior 需访问 Scoped 服务需重新设计 | 当前无此需求；MediatR 模式是成熟方案 |
| `use_middleware<T: Default>` 限制 | 无法注册需配置的 middleware | 需配置的 middleware 用现有 `register()` 或直接 `add_middleware` |

### 不在本次范围

- P0-4、P0-5（已完成）
- 自定义 middleware 的 docbit 适配（若有，按需更新）
- 健康检查的内置探针（DB ping、Redis ping 等）
- IPipelineBehavior 的内置实现（LoggingBehavior、ValidationBehavior）
- IApplicationBuilder trait 的文档章节重写（仅更新引用）
