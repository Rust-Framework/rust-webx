| 决策点 | 选择 | 理由 |
|---|---|---|
| `StaticJsonEndpoint` content_type 扩展 | 增加 `content_type: &'static str` 字段 | 用户已确认；最干净，无新增类型，符合"不容忍兼容性设计"原则 |

#### 改动 4-C：HostBuilder 新增 use_middleware

**文件**：[crates/host/src/server.rs](file:///e:/GitCode/RF/rust-webx/crates/host/src/server.rs)（HostBuilder impl 块，建议在 `add_memory_cache_with` 之后 L210 附近）

**新增方法**（参考 `add_memory_cache` L197-202 的注册模式）：
```rust
/// Register a middleware by type.
///
/// Middleware `T` is registered as Singleton in the DI container and
/// automatically collected by `provider.get_all::<dyn IMiddleware>()`
/// during `build()`.
///
/// ```ignore
/// Host::builder()
///     .use_middleware::<RequestIdMiddleware>()
///     .build()
/// ```
pub fn use_middleware<T: IMiddleware + Default + 'static>(mut self) -> Self {
    self.service_configs.push(Box::new(|svc| {
        svc.singleton::<Arc<dyn IMiddleware>>(|_| Arc::new(T::default()) as Arc<dyn IMiddleware>)
    }));
    self
}
```

**约束**：`T: IMiddleware + Default + 'static`。需配置的 middleware（如 CorsMiddleware）继续在 `build()` 内部直接 `add_middleware`，不变。

#[derive(Debug, Clone, serde::Serialize)]
pub struct HealthCheckEntry {
    pub name: String,
    pub status: String,        // "pass" | "warn" | "fail"
    #[serde(skip_serializing_if = "Option::is_none")]
    pub detail: Option<String>,
}

impl HealthCheckRegistry {
    // ... existing new/register/all_healthy ...

    /// 返回所有健康检查项的当前快照。
    pub fn snapshot(&self) -> Vec<HealthCheckEntry> {
        self.checks
            .lock()
            .map(|c| {
                c.iter()
                    .map(|(name, f)| {
                        let s = f();
                        HealthCheckEntry {
                            name: name.clone(),
                            status: s.status.to_string(),
                            detail: s.detail.clone(),
                        }
                    })
                    .collect()
            })
            .unwrap_or_default()
    }

    /// 计算整体状态：fail 优先于 warn 优先于 pass；空列表视为 pass。
    pub fn overall_status(&self) -> &'static str {
        self.checks
            .lock()
            .map(|c| {
                let entries: Vec<_> = c.iter().map(|(_, f)| f()).collect();
                if entries.is_empty() {
                    "pass"
                } else if entries.iter().any(|e| e.status == "fail") {
                    "fail"
                } else if entries.iter().any(|e| e.status == "warn") {
                    "warn"
                } else {
                    "pass"
                }
            })
            .unwrap_or("fail")  // Mutex poisoned →保守 fail
    }
}
```

/// Register a health check probe.
///
/// Health checks are exposed via `/health` and `/health/ready` endpoints
/// following RFC 8407 (`application/health+json` content type).

pub fn add_health_check<F>(mut self, name: impl Into<String>, check: F) -> Self

```rust
/// 构建 RFC 8407 health+json 响应体。
fn build_health_response(registry: &HealthCheckRegistry) -> Vec<u8> {
    let entries = registry.snapshot();
    let overall = registry.overall_status();
    let body = if entries.is_empty() {
        serde_json::json!({ "status": overall })
    } else {
        serde_json::json!({
            "status": overall,
            "checks": entries
        })
    };
    serde_json::to_vec(&body).unwrap_or_default()
}
```

## 假设与风险

### 假设

1. `StaticJsonEndpoint` 构造点仅在 server.rs L375/388/398/407 共 4 处（已通过 grep 验证）
2. `HealthCheckRegistry::new()` 返回 `Arc<Self>`，与 HostBuilder 字段类型 `Arc<HealthCheckRegistry>` 兼容（已确认 health.rs L42-46）
3. `svc.instance(Arc<T>)` 是 rust_dicore 注册单例的标准 API（与 `add_memory_cache` L198-201 一致）
4. docbit 无 `impl IMiddleware` 和无 `IApplicationBuilder` 引用（已通过 grep 验证，零破坏保证）

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `StaticJsonEndpoint` 字段变更破坏外部构造 | 仅 server.rs 4 处构造点，全部同步更新 | grep 验证无其他构造点 |
| `HealthCheckRegistry::overall_status` Mutex poisoned | 返回 "fail"（保守策略） | 已在实现中处理 |
| `use_middleware<T: Default>` 无法注册需配置的 middleware | CorsMiddleware 等仍走 `build()` 内部 | 已在文档说明约束 |
| 健康 endpoint body 在 `build()` 时预计算 | 运行时添加 health check 不会反映到端点 | 当前设计：所有 check 必须在 `build()` 前注册；未来如需动态可改用 `RequestEndpoint` |

### 不在本次范围

- 内置健康探针（DB ping、Redis ping 等）
- 运行时动态健康检查（需改用 `RequestEndpoint` 闭包形式）
- IPipelineBehavior 的内置实现（LoggingBehavior、ValidationBehavior）
- HostBuilder 的 `use_middleware` 链式配置 API（如 `use_middleware::<A>().use_middleware::<B>()` 已天然支持）
