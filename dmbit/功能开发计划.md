# 智算机房管理系统 · 功能开发计划

> **实施进度**（2026-07-22）：P0 完成；大屏改为玻璃态单条统计条 + 产品构成/状态双图去重；brand 改为型号短码（RTX5090 等）；管理端「新增产品」移至搜索栏右侧。未做：公式进 appsettings、CSV 导出。  
> 交互版见 Cursor Canvas：`canvases/dmbit-functional-plan.canvas.tsx`  
> 产品：智算机房管理（直播数据智算机房设备台账）。**只做两件事**：手动维护设备信息；在可视化大屏清晰看到机房设备情况。

## 1. 产品定位

面向 AI 机房的 **算力 / 存储服务器台账 + 展示大屏**。

- 管理员维护产品与规格（数量 / 状态 / 机位 / 参数）
- 访客打开大屏，按产品、状态、数量、容量 PB、算力 MW、机位理解机房现状
- **不做**：算力调度、实时遥测、工单运维、Three.js 机房漫游

## 2. 核心用户旅程

| 角色 | 路径 | 流程 | 成功标准 |
|------|------|------|----------|
| 管理员 | `/admin/login.html` → `/admin/index.html` | 登录 → 产品列表（可展开）→ CRUD 产品/台账 → 大屏自动反映 | 改数量/状态后刷新大屏即同步 |
| 访客 | `/`（公开） | 打开大屏 → 总数与分类小字 + PB/MW → 产品/状态图 → 明细点开参数 | 10 秒内回答「有多少台、结构如何、哪些在跑」 |

## 3. 领域模型

```
Product（产品型号） 1 ─── N Goods（台账明细行）
```

| 实体 | 职责 | 关键字段 |
|------|------|----------|
| **Product** | 可管理的产品型号 | `name`, `code`, `remark`, `sort_order` |
| **Goods** | 该产品下的台账明细 | `brand`（型号短码）, `parameters`, `quantity`, `status`, `location`, `asset_code` |
| **parameters** | 多行文本 | 标准键：机箱 / 主板 / 内存 / 接口 / 扩展 / 电源 / 光模块（存储可另含硬盘、CPU、网卡） |

**brand 语义**：品牌/型号短码（`RTX5090` / `RTX4090` / `定制` / `HC320`），**不是**配置摘要。配置数量写在参数里（如扩展 `RTX5090×6`）。`config_summary` 由参数生成。

### 种子目标结构（四条独立产品）

| 产品 | code | brand 短码 | 数量 | 状态 |
|------|------|------------|------|------|
| 定制算力节点 | `compute-custom` | 定制 | 1800 | 待上架 |
| RTX 5090 算力服务器 | `compute-5090` | RTX5090 | 150 | 运行中 |
| RTX 4090 算力服务器 | `compute-4090` | RTX4090 | 150 | 运行中 |
| 存储服务器 | `storage` | HC320 | 388 | 联调中 |

**反模式（已废弃）**：把 5090/4090/定制塞进同一个「运算服务器」下的三条 Goods；把 `6×RTX5090` 写进 brand。

## 4. 大屏信息架构（去重）

| 数据维度 | 来源 | 呈现 | 视觉权重 |
|----------|------|------|----------|
| 总数 | Σ quantity | 玻璃条主数字 | **最高** |
| 运算 / 存储台数 | code 归类 | 主数字下**小字**（非并列 KPI 卡） | 中 |
| 容量 PB / 算力 MW | 存储盘位公式 / GPU 估算 | 玻璃条侧栏 | **高** |
| 机柜 | 估算 rack_count | 淡化侧栏 | **低** |
| 产品构成 | Product.name | **唯一**占比图（饼） | 高 |
| 状态 | Goods.status | **唯一**状态图（柱） | 高 |
| 机位 / 品牌 / 参数 | 明细表 + 弹层 | 表/弹层 | 中 |

**禁止**：饼图占比 + 品牌柱图占比 + 多 KPI 卡重复同一数量维度。已去掉品牌辅图。

视觉：白底玻璃态（半透明 + blur）+ 蓝紫点缀；突出重点、淡化次要；ECharts（无 Three.js）。

## 5. 后台 UX

- **可展开单表合理**：产品少（约 4 行）、每产品常 1 条 Goods。
- 「新增产品」在**搜索栏右侧**（工具条同行），不占顶栏。
- 产品表单：名称 / 编码 / 备注 / 排序。
- 台账表单：品牌短码、状态、机位、资产编码、数量、单位 + 标准参数 + 附加参数行（不丢键）。
- **注意**：存储种子含扩展参数键；七键表单编辑后再保存可能丢硬盘/CPU 行 → 已做「标准键 + 附加行」。

## 6. MVP vs 后续

| 阶段 | 范围 |
|------|------|
| **MVP** | 产品/台账 CRUD、登录改密、大屏玻璃条+双图+明细、四产品种子、白蓝紫层次 |
| **Phase 1** | 参数可扩展、刷新时间、筛选、公式可配置、CSV 导出 |
| **Phase 2+** | 单机序列号、机柜平面图、多机房、审计、对接监控（明确延后） |

## 9. 验证

```bash
cargo run -p dmbit-host
```

- 大屏：http://localhost:5100/  
- 后台：http://localhost:5100/admin/login.html  
- 账号：`admin@dmbit.local` / `admin123`  

若删除 `app.db*` 时文件被占用（当前常见：宿主进程仍在跑），**先停止 `dmbit-host`，再删除 `dmbit/app.db*` 后重启**，以重新应用四产品种子。静态大屏改动无需重种即可生效。
