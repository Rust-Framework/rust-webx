# 智算机房设备清单 —— CSV 导入数据规范

## 一、CSV 列定义

| # | 列名 | 必填 | 类型 | 说明 |
|---|------|------|------|------|
| 1 | 产品名称 | 首行必填 | 文本 ≤100字 | 设备大类名称，如"运算服务器"、"存储服务器" |
| 2 | 产品编码 | 必填 | 文本 ≤50字 | 全局唯一，建议英文大写+短横线，如 `CMP-SRV`、`STO-SRV` |
| 3 | 类别 | 必填 | 枚举 | `算力`/`存储` 或 `compute`/`storage`。导入时自动规范化为英文 |
| 4 | 规格编码 | 必填 | 文本 ≤50字 | 全局唯一，格式 `{产品编码缩写}-{特征}`，如 `CMP-BASE`、`STO-8TB` |
| 5 | 品牌 | 必填 | 文本 ≤100字 | 品牌短码，如"定制"、"华为"、"supermicro" |
| 6 | 参数 | 可选 | 多行文本 | 机箱参数，格式见第四节 |
| 7 | 单位 | 必填 | 文本 ≤20字 | 默认"台" |
| 8 | 数量 | 必填 | 整数 ≥0 | 该规格计划采购/部署的总台数 |
| 9 | 部件类型 | 部件行必填 | 枚举 | `加速卡`/`硬盘` 或 `accelerator`/`disk`/`gpu`/`npu`/`hdd`/`ssd` |
| 10 | 部件型号 | 部件行必填 | 文本 ≤80字 | 如 `RTX5090`、`DC HC320`、`Ascend 910B` |
| 11 | 容量 | 硬盘必填 | 容量字符串 | 如 `8TB`、`960GB`、`8000`（纯数字=GB）。加速卡留空 |
| 12 | 单台数量 | 部件行必填 | 整数 ≥1 | 每台设备安装该部件的数量，如 RTX5090×6 填 `6` |
| 13 | 备注 | 可选 | 文本 ≤500字 | 产品级别的备注说明 |
| 14 | 排序 | 可选 | 整数 | 控制列表显示顺序，小的在前 |

## 二、核心概念关系

```
产品（Product）                          1:N  规格（Spec）                     1:N  部件（SpecComponent）
├─ 名称、编码、类别（算力/存储）              ├─ 规格编码（唯一）                    ├─ 部件类型（加速卡/硬盘/NPU）
└─ 例：CMP-SRV = 运算服务器                   ├─ 品牌、参数、单位                    ├─ 型号
                                            ├─ 数量（预期台数）                ├─ 容量（仅硬盘）
                                            └─ 例：CMP-5090 = RTX5090配6张        └─ 单台数量
```

**一行 CSV 可以描述一个完整规格 + 第一个部件**。同一规格有多个部件时，使用"稀疏续行"：

```
首行：全部字段填满（产品 + 规格 + 第一个部件）
续行：只填 规格编码 + 部件四列（9-12），其余留空，自动继承首行数据
```

## 三、导入行为

### 3.1 基本规则

| 场景 | 行为 |
|------|------|
| 产品编码不存在 | 自动创建产品（名称、编码、类别、备注） |
| 产品编码已存在 | 按 CSV 内容**覆盖更新**产品名称/类别/备注 |
| 规格编码不存在 | 自动创建规格 |
| 规格编码已存在 | 按 CSV 内容**覆盖更新**品牌/参数/单位/数量 |
| 部件行非空 | 先删除该规格全部旧部件，再插入 CSV 中的部件（整单替换） |
| 部件行全空 | **不动**数据库中的已有部件 |
| 仅产品行（无规格编码/无品牌/无部件） | 仅创建或更新产品，不操作规格 |

### 3.2 冲突检测

导入分两阶段：

1. **检测阶段**：扫描全部行，检查产品编码/规格编码是否已存在于数据库
2. **确认阶段**：如有冲突，返回冲突列表让用户确认；确认后执行写入

```
冲突场景                      →  用户看到                       →  确认后
CMP-SRV 已存在                →  "产品编码：CMP-SRV"             →  覆盖更新产品字段
CMP-5090 规格已存在            →  "规格编码：CMP-5090"            →  覆盖更新规格字段
```

### 3.3 事务性

整次导入**一个事务**：要么全部成功，要么全部回滚。不会出现"产品创建了但规格没创建"的半成功状态。

## 四、参数字段规范

### 4.1 格式要求

参数字段为多行文本，每行格式：`键：值`（使用中文冒号 `：` 或英文冒号 `:` 均可，导入时自动识别）。

```
机箱：4U服务器机箱
主板：嵌入式工业级主板
内存：SO-DIMM内存
扩展：6槽位PCIe扩展板
电源：定制多路输出电源
光模块：双光千兆
```

### 4.2 标准参数键（推荐但非强制）

| 标准键 | 适用产品 | 说明 |
|--------|---------|------|
| 机箱 | 全部 | 机箱规格 |
| 主板 | 全部 | 主板型号 |
| 内存 | 全部 | 内存规格 |
| 接口 | 运算服务器 | IO 接口 |
| 扩展 | 运算服务器 | PCIe 扩展槽位 |
| 电源 | 全部 | 电源型号/功率 |
| 光模块 | 全部 | 网络光模块 |
| CPU | 存储服务器 | CPU 型号/核数 |
| 网卡 | 存储服务器 | 网卡型号 |

管理后台的表单会自动将上述 7 个标准键（机箱/主板/内存/接口/扩展/电源/光模块）展示为独立输入框，其余键在"附加参数"区域管理。

### 4.3 参数与部件的分工

**重要**：部件数据（显卡型号、硬盘型号、容量、单台数量）必须填写在 CSV 的 `部件类型/部件型号/容量/单台数量` 四列中，**不应**依赖参数文本来承载。

| 信息 | 放哪里 | 为什么 |
|------|--------|--------|
| RTX5090 型号、6张/台 | 部件列（9-12） | 大屏仪表盘按部件表统计卡/盘数量 |
| 机箱、主板、内存 | 参数字段 | 这些是定性描述，不参与数量统计 |
| "RTX5090×6" 写在扩展参数里 | **错误** | 大屏统计不到，导入后数量为 0 |

**反例**（错误做法）：
> 扩展：6槽位PCIe，RTX5090×6  ← 把部件数据混在参数里

**正例**（正确做法）：
> 扩展：6槽位PCIe扩展板          ← 参数只写槽位信息
> 部件列：加速卡 / RTX5090 / — / 6  ← 部件数据独立填写

## 五、数据校验规则

### 5.1 系统自动校验（导入时强制执行）

| # | 规则 | 违反时错误信息 |
|---|------|--------------|
| 1 | 产品编码不能为空 | "产品编码不能为空" |
| 2 | 规格编码必须全表唯一（同一次导入中） | "第N行：同一规格下部件重复" |
| 3 | 产品编码/规格编码跨行一致（续行 vs 首行） | "第N行：同一规格的参数与首行不一致（续行请留空继承）" |
| 4 | 部件类型必须是有效值 | "部件类型无效（支持：加速卡/硬盘）" |
| 5 | 加速卡不能填写容量 | "加速卡部件不应填写容量" |
| 6 | 硬盘容量必须是正数 | "容量必须为正整数 GB" |
| 7 | 单台数量 ≥ 1 | "单台数量至少为 1" |
| 8 | 部件型号不能为空（当部件类型填写时） | "部件型号不能为空" |
| 9 | 数量/排序必须是整数 | "数量必须是整数" |
| 10 | 同一规格下部件不能重复（型号+类型+容量组合） | "同一规格下部件重复" |
| 11 | CSV 表头必须与导出格式一致 | "CSV 表头不正确" |

### 5.2 人工校验清单（导入前手动检查）

| # | 检查项 | 检查方法 |
|---|--------|---------|
| 1 | 数量 = 部件期望总量 / 单台数量？ | CMP-5090: 150台 × 6张/台 = 900张。导入后大屏加速卡汇总应显示 RTX5090 = 900张 |
| 2 | 参数中的硬件描述与实际部件一致？ | CMP-5090 参数写"扩展：6槽位PCIe扩展板"，部件有 RTX5090×6 → 一致 |
| 3 | "不含显卡"规格是否无部件？ | CMP-BASE 计划1800台，部件为空 → 大屏加速卡汇总不应出现 CMP-BASE 的卡 |
| 4 | 存储容量计算正确？ | STO-8TB: 388台 × 36块/台 × 8000GB = 111,744,000GB = 111.7PB |
| 5 | 编码命名一致？ | 运算服务器都归在 CMP-SRV 下，不会出现一个叫 CMP 另一个叫 SRV |
| 6 | 中文/英文混用一致？ | 全选中文"算力/加速卡/硬盘"或全选英文"compute/accelerator/disk"，不混用 |

## 六、维护工作流

### 6.1 新增设备型号

```
1. 导出现有数据：管理后台 → 导出 → 得到 CSV
2. 在 CSV 末尾追加新行（或插入到对应产品下方）
3. 填写产品+规格+部件信息
4. 导入 CSV：管理后台 → 导入 → 选择文件
5. 如无冲突，直接写入；有冲突，确认后覆盖
```

### 6.2 修改已有规格

```
1. 导出 CSV
2. 找到对应规格编码的行
3. 修改参数、数量、部件等
4. 导入 → 系统检测到规格编码冲突 → 确认覆盖 → 完成
```

### 6.3 批量修改（如全部运算服务器换新电源）

```
1. 导出 CSV
2. 用 Excel 查找替换：将所有 CMP-* 行的电源参数从"定制多路输出电源"改为"长城GW-1200W"
3. 导入 → 确认覆盖所有冲突的规格编码
```

### 6.4 定期校验

```bash
# 导出 CSV 后，用以下命令快速统计（PowerShell）
Import-Csv import.csv | Group-Object 产品名称 | ForEach { "$($_.Name): $($_.Count) 行" }
Import-Csv import.csv | Where { $_.部件类型 -ne '' } | Group-Object 部件类型 | ForEach { "$($_.Name): $($_.Count) 个部件" }

# 校验总台数
Import-Csv import.csv | Group-Object 规格编码 | ForEach {
    $row = $_.Group | Select -First 1
    "$($row.规格编码): $($row.数量) 台"
}
```

## 七、示例：正确 vs 错误

### 正确示例

```csv
运算服务器,CMP-SRV,算力,CMP-5090,定制,"机箱：4U
扩展：6槽位PCIe",台,150,加速卡,RTX5090,,6,,2
```
- 参数只写定性描述
- 部件独立填写型号+单台数量
- 大屏能正确统计：150 × 6 = 900 张 RTX5090

### 错误示例

```csv
运算服务器,CMP-SRV,算力,CMP-5090,定制,"机箱：4U
扩展：6槽位PCIe，RTX5090×6",台,150,,,,,,2
```
- 部件列全空
- 显卡信息只写在参数里
- **大屏统计不到任何显卡**——这是一个数据黑洞

### 错误示例 2

```csv
运算服务器,CMP-SRV,算力,CMP-BASE,定制,,台,1800,加速卡,RTX5090,,6,,
```
- CMP-BASE 是"不含显卡"的基础配置
- 但填了 RTX5090 部件
- **大屏会错误地显示 CMP-BASE 有 1800×6=10800 张 RTX5090**

## 八、备份建议

1. **每次导入前先导出**：导出当前数据库的快照，保存为 `backup-YYYYMMDD.csv`
2. **导入后验证大屏**：打开 `/index.html`，确认 KPI 数字和图表与预期一致
3. **版本管理**：将 CSV 文件纳入 Git 管理（如 `inventory/` 目录），每次变更保留提交记录
